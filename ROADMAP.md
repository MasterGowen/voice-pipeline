# Roadmap и идеи расширения TTS Pipeline

Этот документ описывает возможные направления развития проекта, сценарии использования и идеи для новых функций.

## 1. Интерфейсы взаимодействия

### 1.1 Расширенный CLI (Command Line Interface)
Текущая реализация уже поддерживает базовый CLI через `pipx`. Возможные улучшения:
- **Интерактивный режим**: Пошаговый мастер настройки проекта (выбор голоса, скорости, папок).
- **Пакетная обработка**: Поддержка масок файлов и рекурсивной обработки директорий.
- **Управление очередью**: Команды для просмотра статуса, паузы, возобновления и отмены задач.
- **Конвертация форматов**: Встроенная утилита для конвертации выходных файлов (wav -> mp3/ogg) через ffmpeg.
- **Валидация конфигов**: Команда `tts-pipeline check` для проверки корректности JSON-файлов перед запуском.

### 1.2 TUI (Text User Interface)
Идеально для работы в терминале сервера без графической оболочки.
- **Технологии**: `Rich`, `Textual` (Python).
- **Функционал**:
  - Визуализация прогресс-баров для каждого файла.
  - Таблица статусов (в очереди, обрабатывается, ошибка, готово).
  - Логирование в реальном времени в отдельном окне.
  - Горячие клавиши для управления процессом (P - пауза, Q - выход, R - перезапуск).
  - Предпросмотр текста и прослушивание сгенерированных фрагментов прямо в терминале (если терминал поддерживает аудио или через вызов внешнего плеера).

### 1.3 GUI (Graphical User Interface)
Для пользователей, не желающих работать с консолью.
- **Технологии**: `PyQt6`, `Tkinter` или кроссплатформенный `Flet`/`Tauri` (веб-технологии).
- **Функционал**:
  - Drag-and-drop зона для загрузки текстовых файлов.
  - Визуальный редактор настроек (слайдеры скорости, питча, выбор голоса из выпадающего списка).
  - Интерактивная шкала времени (timeline) для собранных глав.
  - Встроенный аудиоплеер с возможностью прослушивания результата до сохранения.
  - Экспорт пресетов настроек.

### 1.4 Веб-интерфейс (Self-hosted Service)
Превращение утилиты в микросервис.
- **Технологии**: `FastAPI` + `React/Vue` или `Streamlit` для быстрого прототипирования.
- **Сценарий**: Развертывание на локальном сервере или VPS. Доступ через браузер с любого устройства в сети.
- **Преимущества**: Возможность совместного доступа для команды (писатель + редактор + звукорежиссер).

## 2. Инструменты разметки и подготовки текста

Одна из самых болезненных точек — подготовка JSON-файлов с разбивкой.

### 2.1 Интерфейс визуальной разбивки (Splitter UI)
- **Проблема**: Длинные тексты нужно разбивать на части оптимального размера для API, сохраняя смысловую целостность.
- **Решение**:
  - Загрузка большого текстового файла (.txt, .docx, .fb2).
  - Автоматическая предварительная разбивка по абзацам или предложениям.
  - Визуальный интерфейс "слияния/разделения" блоков (как в видеоредакторах на таймлайне).
  - Подсчет примерной длительности звучания и стоимости для каждого блока.
  - Экспорт готовой структуры в формат `config/chapters/*.json`.

### 2.2 Интеграция с форматами книг
- Поддержка импорта напрямую из `.fb2`, `.epub`, `.docx`.
- Автоматическое распознавание структуры: Глава -> Параграф -> Диалог.
- Возможность назначения разных голосов для разных персонажей (автоматически или вручную через маппинг имен).

### 2.3 Редактор произношения (Phonetic Editor)
- Интерфейс для добавления пользовательских словарей замен (например, "США" -> "С Ш А", сложные фамилии).
- Поддержка SSML-тегов (если API позволяет) для управления интонацией внутри текста через визуальный редактор.

## 3. Сценарии интеграции и автоматизации

### 3.1 Конвейер для подкастов и аудиокниг
- **Интеграция с FFmpeg**: Автоматическое сведение всех частей в один файл, добавление тишины между главами, нормализация громкости (LUFS), добавление интро/аутро.
- **Метаданные**: Автоматическая запись тегов ID3 (автор, название главы, обложка) в итоговые файлы.

### 3.2 Система контроля качества (QC)
- **Сравнение текста и аудио**: Использование Whisper (локально) для транскрибации полученного аудио и сравнения с исходным текстом (расчет WER - Word Error Rate) для выявления пропусков или галлюцинаций модели.
- **Детекция артефактов**: Анализ аудио на наличие цифровых шумов, резких обрывов или неестественных пауз.

### 3.3 Интеграция с системами контроля версий (Git)
- Хранение текстовых глав в Git.
- CI/CD пайплайн: при пуше новой главы в репозиторий автоматически запускается процесс генерации аудио и коммитится результат в ветку `audio-assets`.

### 3.4 Мультиязычность и перевод
- Интеграция с API перевода (DeepL, Google Translate) перед озвучкой.
- Сценарий: Загрузка текста на русском -> Автоматический перевод на английский/испанский -> Озвучка носителями соответствующих языков.

## 4. Технические улучшения ядра

### 4.1 Кэширование и дедупликация
- Хэширование текстовых блоков. Если текст не изменился, не запрашивать API повторно, а брать готовое аудио из кэша. Экономия токенов и денег.

### 4.2 Асинхронность и производительность
- Полная перепись на `asyncio` для параллельной обработки нескольких глав одновременно (с учетом лимитов RPM/API rate limits).
- Поддержка очередей задач через Redis/RabbitMQ для распределенной обработки на нескольких машинах.

### 4.3 Абстракция провайдеров
- Создание унифицированного интерфейса `TTSEngine`.
- Легкое переключение между провайдерами: OpenRouter (Gemini), ElevenLabs, Azure TTS, Google Cloud TTS, локальные модели (Coqui TTS, Silero).
- Конфигурация через единый файл с выбором провайдера для каждой задачи.

## 5. Примеры пользовательских сценариев (User Stories)

1. **"Ленивый автор"**:
   - Пишет книгу в Obsidian/Notion.
   - Экспортирует главу в проект.
   - Запускает `tts-pipeline watch` (режим наблюдения).
   - При сохранении файла книга автоматически озвучивается и обновляется в плеере.

2. **"Студия аудиокниг"**:
   - Режиссер загружает книгу в веб-интерфейс.
   - Размечает диалоги, назначая голоса персонажам.
   - Запускает рендер фермой (несколько ПК).
   - Система собирает черновик, режиссер правит сложные моменты в редакторе.
   - Финальный экспорт в стерео с музыкой и шумами.

3. **"Обучение языкам"**:
   - Студент загружает статью на иностранном языке.
   - Система генерирует аудио с замедленной скоростью.
   - Параллельно создается файл с субтитрами (SRT) для изучения.
